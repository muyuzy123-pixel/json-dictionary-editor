# 平台差异与验收边界

以下行为来自候选源码检查；共享核心测试覆盖的项目另行标明。源码中存在某项行为不等于已经完成对应系统上的 GUI 验收。

| 项目 | macOS | Windows | 本次证明范围 |
| --- | --- | --- | --- |
| 现有版本 | 1.0.0，构建号 1 | 1.0.1 | 源码版本字段；不同实现不强制同版本 |
| UI 技术 | SwiftUI / AppKit，macOS 13 最低部署目标 | Win32 / C++17，x64 和 ARM64 构建目标 | 构建配置；系统兼容仍依赖实机验证 |
| 数据核心 | Swift `JSONModel` / `OrderedJSONCodec` | C++ `json_core` | 保持独立；共享测试直接编译原源文件 |
| UTF-8 BOM | 核心及文档打开拒绝 | 核心拒绝；文件层读取剥离、保存恢复 | 核心拒绝有共享样例；文件层为源码检查 |
| 规范等价键 | Swift String 将 NFC/NFD 规范等价键当作重复 | 解码后 UTF-8 字节不同可并存 | 两端不同期望均有共享样例 |
| CRLF 格式识别 | 仅使用 CRLF 的输入被识别为紧凑、无末尾 LF | 按 LF 字节识别缩进与末尾换行，输出统一 LF | 四空格 CRLF 输入有共享样例；本次未修改差异 |
| 排序 | `localizedStandardCompare` 自然语言/本地化比较 | 无符号 UTF-8 字节序 | 源码检查；不能声称跨平台排序一致 |
| 核心深度 | 未设置对应显式上限 | 512 层容器；解析及校验均检查 | C++ 512 接受、513 拒绝有共享样例；Swift 不做无界压力测试 |
| 核心节点数 | 未设置对应显式上限 | 解析上限 250000，含根 | 源码检查，不作为大文件性能保证 |
| GUI 文件与节点限制 | 未设置 Windows 同款限制 | 16 MiB 文件、50000 节点；格式化后大小也检查 | 源码检查，未运行 Windows GUI 边界验收 |
| Windows 编辑控件限制 | 无对应 Windows 控件限制 | 原始 JSON 编辑约 4 MiB UTF-8/4 Mi UTF-16 单元；检查器 1 Mi UTF-16 单元；键 65535 单元，特殊值还会转入原始编辑路径 | 源码检查；各限制作用位置不同，不能仅按文件字节换算可编辑性 |
| 保存实现 | SwiftUI `FileDocument` 返回 UTF-8 `FileWrapper`，交由系统文档机制处理 | 自定义同目录暂存、文件身份与 SHA-256 比较、`ReplaceFileW` / `MoveFileExW` 和保存后重读检查 | 不能把一端的保存验证结果套用到另一端 |
| 完整 GUI 验收 | 历史有若干局部界面操作记录，未对本候选复验；无完整 GUI 验收 | 本次没有 Windows 实机 GUI 验收 | 构建、核心测试、局部操作与窗口存活检查均不等同完整 GUI 验收 |
| 1.0.1 分隔条修复 | 不适用 | 源码改成竖线与中央拖动柄、10 DIP 命中宽度 | **修复后的 Windows 实机视觉确认仍缺失，不得标为通过** |

更详细的数据约定见 [共享数据规则](data-rules.md)。实际执行环境和结果以本候选的验证记录为准。共同缺项应保持“未验证”；拟覆盖的额外系统或架构应写“计划支持”，不能从交叉编译结果直接推导“已经支持并通过”。
