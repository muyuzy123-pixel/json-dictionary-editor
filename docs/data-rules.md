# 共享数据规则

这份规则描述两个现有独立实现的共同数据约定及已知例外。整理候选时没有合并解析器或改变产品行为。macOS 使用 Swift 的 `JSONModel` / `OrderedJSONCodec`；Windows 使用 C++ 的 `json_core`。

## 共同约定

| 项目 | 现有行为 |
| --- | --- |
| 文档根 | 编辑器文档必须是对象。核心解析器可以解析数组、字符串、数字、布尔值和 null 作为根；文件打开/保存与根节点编辑另行要求对象。 |
| 类型 | 字符串、数字、布尔值、null、对象、数组保持各自类型。例如 `"2"` 不自动变为 `2`。 |
| 顺序 | 对象保存成员输入顺序，数组保存元素顺序。格式化不排序；显式排序是单独操作，排序规则存在平台差异。 |
| 数字 | 保存词法文本，不先转换成浮点数。`1.2300e+04`、`9007199254740993`、`1e9999`、`-0` 可以按原数字文本写回；接受语法不表示可以在本机浮点类型中运算。 |
| 数字语法 | 可有负号，整数部分不允许多余前导零；小数点及指数后必须有数字。不接受 `+1`、`01`、`NaN`、`Infinity`。 |
| 编码 | 核心接受有效 UTF-8，不支持 UTF-16 数据。字符串支持 JSON 转义、有效 Unicode 代理项对，拒绝孤立代理项、无效 UTF-8 和未转义控制字符。文件层的 BOM 行为见下一节。 |
| 对象键 | 空键允许；每个对象内检查重复键，转义先解码，因此 `"a"` 与 `"\u0061"` 冲突。不同对象可以使用同名键。规范等价 Unicode 键的判断存在平台差异。 |
| JSON 边界 | 只接受一个完整值及 JSON 空白（空格、制表符、CR、LF）；拒绝注释、尾逗号、空文件和第二个顶层值。 |
| 输出 | UTF-8；紧凑、2 空格、4 空格、制表符四种格式。漂亮格式输出 LF；可选择末尾 LF。输出保持数据与数字文本，但不承诺保留原文件字节、转义写法、空白或 CRLF。 |
| 格式识别 | 对仅使用 LF 的文本：无 LF 时识别为紧凑格式；有 LF 时检查后续首个带缩进的行，以首字符为制表符、至少 4 个空格或不足 4 个空格选择格式，无缩进时回落到 2 空格。以最后一个字符是否为 LF 记录末尾换行。CRLF 检测存在下述差异。 |

## 必须保留的差异

- **Unicode 键相等性：** Swift `String` 按规范等价判断相等，因此 `é`（U+00E9）与 `é`（U+0065 U+0301）同处一个对象会被拒绝。C++ 对解码后的 UTF-8 字节比较，接收这两个键。本次不统一策略。Swift 的比较行为也不意味着写出时会将所有字符串主动转为 NFC；共享样例检查了单独 NFD 字符串的输出字节。
- **UTF-8 BOM：** 两个核心解析器都拒绝开头的 BOM。Windows 文件读取层先移除 UTF-8 BOM，保存时按原标记补回；macOS 文档直接将原始数据交给解析器，会拒绝带 BOM 文件。共享核心测试不能作为 Windows BOM 文件往返已验收的证据。
- **CRLF 格式识别：** Swift 的现有 `String` 检测按字符处理 CRLF，会将只用 CRLF 的缩进文档识别为紧凑且无末尾 LF；C++ 按 LF 字节检测缩进与末尾换行，写出时使用 LF。共享样例实测了 CRLF 四空格文档在 Swift 写成紧凑、C++ 写成四空格加末尾 LF 的差异。本次仅记录，不修正行为。
- **资源限制：** Windows 核心解析限制 512 层对象/数组嵌套、250000 个节点（根计一个节点）；核心校验器还检查嵌套层数，但不以同一节点数上限限制所有内存操作。Windows GUI 进一步限制文件大小、节点数和编辑控件长度。macOS 当前源码没有对应显式统一限制；这不代表无限容量或已验证安全的大文件支持。

当前适合两端互换的输入是：无 BOM 的 UTF-8 对象文档；每个对象中不放规范等价重复键；控制在 Windows GUI 上限以内，并对实际文件做性能确认。不要依赖两端显式排序产生相同结果。

## 样例与证明范围

[共享样例](../tests/fixtures/cases.json) 与 [运行说明](../tests/README.md) 直接驱动两个现有核心，检查接受/拒绝和输出的 UTF-8 字节。例外使用明确的平台期望，避免把已知差异隐藏成通过或擅自修改产品。

测试包括数字词法、顺序和类型、Unicode 与控制字符、重复键及规范等价差异、无效编码、根对象限制、非法 JSON、四种输出格式、格式识别、CRLF 到 LF 和末尾换行，以及 C++ 512/513 层边界。没有覆盖全部 JSON 组合、Windows 文件 BOM 层、250000 节点边界、GUI 容量边界、并发保存、输入法、鼠标键盘交互、DPI 或无障碍。
